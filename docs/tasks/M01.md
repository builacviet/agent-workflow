## Acceptance criteria

1. **AC01 — Provenance:** Cite exact CURRENT code/line symbols and merged CL-12 TARGET decisions at pinned baseline. Label each statement SOURCE FACT, TARGET PROPOSAL, HISTORICAL or UNKNOWN when meaningfully disputed. No production or native-Linux proof inferred.
2. **AC02 — Authority and identity:** Define owners of WFC/dispatch/Executor/remote truth, immutable task/round/input/dispatch/stage/engine/artifact identity and no-cross-system-atomicity limitation.
3. **AC03 — Lifecycle contract:** Specify **per-stage** durable create intent → immutable handle persisted → start intent → stage result → stop/reap intent → verified settlement **before next stage**, with independent Controller/Executor journaling, late-command proof and fenced unknown. Wrong ID/DB/engine or late create must never imply safe name-based cleanup **or slot release**, including under Owner-approved quarantine: require technical proof late commands cannot act on existing/reassigned resources after restart/restore; otherwise retain fence.
4. **AC04 — Publish reconciliation:** Specify **atomic lease/generation verification plus per-operation send reservation in the same local transaction before each push/POST/PATCH**, including suspended-before-send and late requests, expected commit/parent/ref, stable PR identity/head/base/repo/actor/body and independently validated receipt. Unsent/sent/unknown reserved operations retain writer fence; `REMOTE_PARTIAL`/`PUBLISH_UNCERTAIN` cannot finalize; never blindly repeat or force-push.
5. **AC05 — WFC coordination:** Require one verified physical SQLite DB and **same serialized writer arbitration** for manual handoff and auto admission; distinct manual authority. Automated single local transaction for receipt/finalization ID + `DONE` + `READY_IN_REVIEW` only after **independently verified GitHub ref+PR receipt (`PUBLISH_VERIFIED`), all stages fully settled, and technically verified loss/containment of residual write credentials**. Owner authorization alone does not establish these technical gates. Specify lost commit acknowledgement read-by-ID and preserve already-progressed reviews, exact SHA and two-round policy.
6. **AC06 — Recovery matrix:** Distinct outcome/evidence/disposition for complete publish+handoff, remote partial, missing handoff, verified no effect, unknown/conflict, **revoke uncertain** and **handoff committed but final cleanup failed**. Require verified-owned stop/reap independent of release; **no release on quarantine/approval without proof all late commands and writing principals can no longer affect resources**; conditional audited disposition+slot release in one exact-dispatch transaction; no unimplemented command represented as CURRENT.
7. **AC07 — Test contract:** For each crash/uncertain boundary specify **CURRENT as-built characterization separately from TARGET expected safety** on both sides of each local commit and external effect: invalid ownership, late create, handle/start/stop/reap loss, stale PR body, lost push/POST/PATCH, both manual/admission races, split local writes and lost finalization commit response. **M01 test execution NOT RUN.**
8. **AC08 — Decision register:** Explicitly list D-01/D-02/D-03 proposed defaults and unresolved choices, **split-ledger/restore authority under D-02A (downstream CL-12.4/CL-11), actor/role decisions under D-02C, late-command evidence, mutation-reservation and credential non-write gates**, schema/migration dependencies and separate M01 acceptance, PR merge, M02 start, implementation and cutover decisions. No unregistered D-04/D-06 gate is implied. Owner approval required before contract status changes to accepted.
9. **AC09 — Review integrity:** Verify actual PR base, HEAD, exactly these two changed paths and local Markdown relative links; independent reviewer checks the complete spec/source truth at exact head. Maximum 2 review rounds; Owner alone merges or signs off.
